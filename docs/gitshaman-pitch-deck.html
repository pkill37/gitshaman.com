01 / The problem
context is the bottleneck

Modern repositories are searchable — but still hard to understand.

The friction is not finding a file. It is building a trustworthy mental model across files, symbols, services, and history.

01

Fragmented context

Docs, source, search, and diagrams live in separate tools. Engineers stitch the story together by hand.

02

Expensive onboarding

New contributors learn architecture through guesswork, tribal knowledge, and repeated questions.

03

Opaque change

Finding the right symbol is easy. Knowing what depends on it — and why — is the hard part.

GitShaman frames the problem as code comprehension02 / 08

05 / Why now
the codebase is the new interface

AI can write code faster. Teams still need to understand what they already have.

AI increases the need for context

More generated code means more review, more dependencies, and more questions about system behavior. The durable advantage is a better model of the repository.

Local data is a product requirement

Private code, regulated environments, and developer trust make local indexing and portable workspaces a natural foundation.

06 / The advantage
depth over novelty

GitShaman compounds where generic search stops.

Repository-native

Understands files, symbols, guides, indexes, and the shape of the project — not just text matches.

Local-first

The CLI analyzes a worktree and opens a local workspace. The core loop does not require sending source away.

Open-source gravity

Curated public repositories create a visible corpus, a teaching surface, and a path to community contribution.

Defensible workflow

Guides → source → symbols → relationships → discussion is a connected journey. Each step makes the next one more valuable.
